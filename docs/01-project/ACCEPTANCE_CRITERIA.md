## 1. Verification Philosophy & Spec-First Governance

1. **No Unmeasured Claims:** Every performance, latency, recovery, or concurrency metric displayed during the pitch must be measured live from the running system. Pre-claimed static numbers (e.g., "MTTR 3 s") are prohibited.
2. **Defense-in-Depth Verification Layers:**
   - **Layer A — Formal Control-Plane Verification (`Quint` `rhp1.qnt`):** Bounded model checking and randomized symbolic simulation of state transitions, offer caps, and lease invariants (`Person A`).
   - **Layer B — Database Enforcement (PostgreSQL 16):** Partial unique indexes (`one_lease`), deferred constraint triggers (`i1_pending_deadline`), session-GUC lock triggers (`rhp_require_lock`), hash-chain guards (`rhp_event_guard`), and JSONB allowlist checks (`rhp_detail_ok`).
   - **Layer C — Concurrency, Idempotency & Chaos Harness (`pytest` + `Toxiproxy`):** 200-way `asyncio.Barrier` race tests, 8-case idempotency matrix, 6 mutation tests (`M1`–`M6`), and 8 network-toxic profiles.
   - **Layer D — Independent Runtime Monitor (`Person B`):** A standalone Python process (`rhp_monitor` read-only DB role) written strictly from §3 prose without importing a single line of server code, performing continuous event-fold differential checks against `referral` rows.
